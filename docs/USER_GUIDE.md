## 1. Подготовка среды

Рекомендуется Python 3.13. Вычисления выполняются на процессоре; видеокарта, FFmpeg и подключение к интернету во время моделирования не требуются. Интернет нужен для первоначальной установки зависимостей.

Откройте терминал в корне `lab3_dla`, где находится `main.py`.

### Windows / PowerShell

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --help
```

Эти команды запускают Python непосредственно из виртуального окружения. Изменять политику выполнения PowerShell и активировать окружение не требуется.

### Linux / macOS

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --help
```

В следующих примерах команда `python` обозначает интерпретатор созданного окружения. В PowerShell вместо неё можно использовать `.\.venv\Scripts\python.exe`, в Linux/macOS — `.venv/bin/python`.

## 2. Первый расчёт

```bash
python main.py simulate --particles 3000 --p 1 --seed 42 --out results/demo --animate
```

Будет выращен кластер из 3000 узлов, включая центральный зародыш. При `p=1` частица закрепляется при первом достижении свободного узла, соседнего с кластером. Неподвижные частицы не перемещаются и не отделяются.

Первый запуск может занять больше времени из-за компиляции Numba. Последующие расчёты используют скомпилированное ядро. Процесс состоит из множества случайных блужданий; одинаковое число частиц не гарантирует одинаковое время работы.

Выходной каталог содержит координаты кластера `cluster.npz`, численные характеристики и изображения. При `--animate` дополнительно создаётся GIF роста. В нём показаны последовательные состояния фактически рассчитанного кластера. Цвет частицы обозначает порядок её присоединения.

Чтобы сначала проверить установку на небольшом расчёте:

```bash
python main.py simulate --particles 300 --p 1 --seed 42 --out results/smoke
```

## 3. Основные параметры

| Параметр | Смысл |
|---|---|
| `--particles` | Итоговое число частиц вместе с зародышем |
| `--p` | Вероятность прилипания на каждом контактном такте; `0 < p <= 1` |
| `--seed` | Начальное состояние генератора случайных чисел |
| `--out` | Каталог результатов |
| `--animate` | Создать анимацию роста после расчёта |

Полный список флагов конкретной команды доступен через `--help`:

```bash
python main.py simulate --help
python main.py experiments --help
python main.py validate --help
python main.py render --help
```

Все длины выражены в шагах решётки. Счётчик присоединившихся частиц не является временем в секундах. Параметр `p` не задаёт силу притяжения к центру.

## 4. Повторная визуализация

Сохранённый `cluster.npz` содержит исходные координаты в порядке присоединения и метаданные. Для изменения оформления пересчитывать случайные блуждания не требуется:

```bash
python main.py render --input results/demo/cluster.npz --out results/rendered --animate
```

Анимация использует фиксированную камеру, чтобы масштаб структуры был сопоставим между кадрами. Свечение добавляется только при отрисовке и не меняет координаты или геометрические измерения.

## 5. Проверка свободного блуждания

```bash
python main.py validate --trials 20000 --steps 400 --out results/validation
```

Без кластера выполняется ансамбль независимых блужданий. Для единичного шага проверяется точное равенство `E[r²(k)] = k`. В результатах сопоставляются измеренное среднее, теоретическое значение и стандартная ошибка среднего.

Относительная ошибка в одном запуске не обязана быть нулевой. Для стохастического расчёта важен её масштаб относительно статистической ошибки. Проверка не означает, что каждый отдельный путь должен иметь длину смещения, равную корню из числа шагов.

## 6. Серия экспериментов

```bash
python main.py experiments --particles 3000 --replicates 6 --out results/study
```

Серия предназначена для исследования режимов прилипания, статистического разброса и влияния окружностей запуска/перезапуска. Число реализаций задаётся параметром `--replicates`; конкретные `seed` сохраняются в результатах.

Основной итоговый файл — `summary.json`. Он связывает параметры, таблицы и пути к графикам. Координаты отдельных реализаций сохраняются для воспроизведения измерений и изображений. Готовая опубликованная серия располагается в `docs/results`; рабочие пересчёты — в `results`.

Для сравнения разных значений `p` используется одинаковое число присоединившихся частиц. Сопоставлять только красивые картинки недостаточно: анализируются радиус инерции, эффективная размерность и разброс между реализациями. Обозначение «среднее ± стандартное отклонение» описывает изменчивость кластеров, а не доверительный интервал среднего.

## 7. Подготовка материалов README и отчёта

После пересчёта серии обновите демонстрационные изображения, анимации и публикационную копию численных данных:

```bash
python scripts/build_readme_media.py --study results/study
```

Затем создайте отчёт из обновлённой публикационной серии:

```bash
python -m pip install -r requirements-dev.txt
python scripts/build_report.py --summary docs/results/summary.json
```

В дополнительных зависимостях находится `python-docx`, необходимый для пересборки документа. Отчёт создаётся в `report/Отчет_ЛР3_DLA.docx`. Титульного листа нет: документ начинается с содержания. Числа и рисунки берутся из указанного JSON и файлов проекта. Если входные данные отсутствуют, сначала выполните расчёты; генератор не подставляет вымышленные результаты.

Содержание Word является полем. Если после изменений номера страниц не обновились, откройте документ в Word, нажмите `Ctrl+A`, затем `F9` и выберите обновление оглавления целиком. После добавления собственного титульного листа содержание нужно обновить ещё раз.

Отчёт DOCX и его PDF-версия хранятся локально и не включены в репозиторий. После пересборки или редактирования документа экспортируйте PDF из Word, чтобы обе версии содержали одинаковые результаты.

## 8. Автоматические тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют свойства модели, сохранение данных, геометрические измерения и построение изображений. Численный эксперимент со свободным блужданием выполняется отдельной командой `validate`.

## 9. Воспроизводимость

Для повторения результата сохраните параметры, `seed`, версии Python/NumPy/Numba, backend и версию исходного кода. Один `seed` без остальных сведений не описывает эксперимент полностью. Метаданные расчёта находятся внутри NPZ, а параметры серии и сведения о среде — в `summary.json`.

Сравнение времён выполнения имеет смысл на одной машине и после прогрева Numba. Время компиляции, отрисовки и сохранения GIF не следует приписывать самому алгоритму роста.

## 10. Возможные затруднения

- **Нет команды `python`.** Используйте полный путь к интерпретатору `.venv`, приведённый выше.
- **Numba не загружается.** Проверьте версию Python, устанавливайте зависимости в новое окружение из `requirements.txt`. Python 3.13 выбран для совместимости зафиксированных зависимостей.
- **GIF виден в GitHub, но в редакторе показан текст ссылки.** Откройте Markdown Preview в VS Code сочетанием `Ctrl+Shift+V`. Сам файл `README.md` содержит исходный Markdown.
- **Не хватает места для роста или достигнут лимит шагов.** Расчёт завершится ошибкой. Увеличьте соответствующий предел из `simulate --help`; не принимайте обрезанный кластер за завершённый результат.
- **Серия работает заметно дольше одного примера.** Она включает независимые повторы и варианты границ. Для проверки установки сначала используйте небольшой `--particles`; научные выводы делайте по полной сохранённой серии.
