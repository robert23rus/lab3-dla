# Подготовка к публикации в GitHub

[← Вернуться к README](../README.md)

Проект подготовлен для будущей публикации. Эта инструкция перечисляет состав репозитория; сама по себе она не выполняет публикацию и не предполагает существования удалённого репозитория ЛР № 3.

## Что опубликовать

Сохраните следующую структуру относительно корня проекта:

| Файл или каталог | Зачем нужен |
|---|---|
| `README.md` | Главная страница проекта с относительными ссылками и анимациями |
| `main.py` | Точка запуска команд |
| `requirements.txt` | Библиотеки модели и визуализации |
| `requirements-dev.txt` | Зависимости для тестов и генерации DOCX |
| `requirements-lock.txt` | Полный набор версий проверенного окружения |
| `pytest.ini` | Настройки проверки проекта |
| `.gitignore` | Исключение окружения, кешей и рабочих результатов |
| `.gitattributes` | Правила перевода строк и бинарных файлов |
| `dla/` | Все исходные модули Python |
| `tests/` | Проверки модели, анализа, команд и отрисовки |
| `scripts/` | Генераторы медиа и отчёта |
| `docs/` целиком | Теория, инструкции, реальные данные, графики, GIF и манифест |

Особенно важно включить `docs/media/dla-growth.gif` и `docs/media/sticking.gif`. README ссылается на эти файлы. Их имена и регистр должны совпадать с разметкой.

В `docs/data` находятся 43 небольших NPZ: 42 расчёта статистической серии и отдельный кластер для главной анимации. Эти архивы позволяют заново построить рисунки и проверить характеристики. Они входят в публикуемый набор данных.

Папка `docs/results` содержит сохранённые результаты исследования и тоже публикуется. Правило `/results*/` в `.gitignore` относится к рабочим каталогам в корне проекта, поэтому не исключает `docs/results`.

## Что оставить на компьютере

- `report/` — отчёт DOCX и PDF; он исключён из публикации.
- `.venv/` — установленное виртуальное окружение; другой пользователь создаёт своё по `requirements*.txt`.
- `__pycache__/`, `.pytest_cache/` — служебные кеши Python и pytest.
- `*.pyc`, `*.pyo`, `*.nbc`, `*.nbi` — скомпилированные файлы Python и Numba.
- Корневые `results/`, `results_demo/` и другие `results*` — рабочие расчёты, повторы и промежуточные изображения.
- Временные файлы Word вида `~$Отчет_ЛР3_DLA.docx` и файлы `*.tmp`.
- Само содержимое `.git/` при ручной загрузке через веб-интерфейс; Git управляет этим каталогом самостоятельно.

Не добавляйте общие правила исключения `*.gif`, `*.png`, `*.npz`, `*.docx` или `*.pdf`: эти форматы содержат необходимые медиа, данные и документы проекта.

## Перед первым коммитом

1. Убедитесь, что `README.md` находится в корне рядом с `main.py`, а `docs` и `report` сохранили структуру.
2. Откройте README в Markdown Preview и проверьте обе анимации. В VS Code используется **Ctrl+Shift+V**.
3. Выполните тесты из корня проекта:

   ```powershell
   .\.venv\Scripts\python.exe -m pytest
   ```

4. Просмотрите список файлов в GitHub Desktop. В нём должны быть код, документы и содержимое `docs`; окружение и кеши должны отсутствовать.
5. Создайте коммит с понятным сообщением, например `Add DLA simulation, experiments and visual documentation`.

Подходящее имя будущего репозитория: **`lab3-dla`**.

## После будущей публикации

Откройте главную страницу репозитория и проверьте:

- README отображается как оформленная страница;
- видны обе GIF, а не только подписи к ним;
- ссылки открывают теорию, руководство и отчёты;
- в репозитории есть `docs/data`, `docs/media` и `docs/results`;
- окружение `.venv`, кеши и рабочие корневые `results*` не попали в список файлов.

Пути в README относительные, поэтому для их работы достаточно сохранить структуру каталогов. Ссылки на локальные диски вида `C:\...` и внешние сервисы хранения изображений не требуются.
